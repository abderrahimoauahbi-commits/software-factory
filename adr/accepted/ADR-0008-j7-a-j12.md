# ADR-0008 — Jalons J7 à J12 : Bootstrap complété, reprise, acceptation, générique, exploitation, auto-audit

| Champ | Valeur |
|---|---|
| Identifiant | ADR-0008 |
| Statut | accepté (« valide et continue pour tous », 15/10/2026) |
| Date | 2026-10-15 |
| Propriétaire | Factory Owner (humain) |
| Rédaction | agent de construction (Claude Opus 5.5) |

## Décisions

| Jalon | Décision |
|---|---|
| J7 | Le Bootstrap vérifie `AGENT_CONTEXT.md` (nom neutre fixé par `bootstrap.yaml`), rapporte `WORKTREE_ROOT`, ajoute le vocabulaire du Master §56 (KNOWN / DECLARED / UNKNOWN). **W1 projetée** dans la configuration de projet de la Factory (`.claude/settings.json` : refus + garde PreToolUse `scripts/hooks/garde_approbations.py` + contournement interdit) : configuration **de la Factory**, pas des réglages utilisateur ; portée = sessions ouvertes dans FACTORY_ROOT. La vérification de ces protections est faite par **l'adaptateur** du runtime (le cœur reste générique). La Factory reçoit son propre `AGENT_CONTEXT.md` et un `CLAUDE.md` qui l'importe |
| J8 | Exercice de reprise `drill` : restauration dans un répertoire neuf + `factory check` + suite du cœur exécutés DEPUIS la copie restaurée ; mesure du RTO. Constat F-BACKUP (âge de la dernière archive, liste seulement). RPO non fixé : alerte à 24 h en attendant |
| J9 | Tests d'acceptation de la Factory (`core/tests/test_fat.py`) contre la configuration RÉELLE ; nouvelle règle de validation `ACTIVE_WITHOUT_APPROVAL` (un état approuvé/actif sans approbation enregistrée est rejeté) |
| J10 | Deuxième manifest fictif d'une autre pile (TypeScript/Node) ; même cœur, décisions dérivées des seuls manifests. **Défaut corrigé** : résolution d'un exécutable vers la mauvaise fiche d'outil (`npm` → `npm-audit`) ; désormais identifiant exact prioritaire, sinon correspondance unique, sinon refus pour ambiguïté |
| J11 | Manuel d'exploitation `docs/operations/runbook.md` ; toute commande citée est confrontée à la grammaire de la CLI et aux scripts (`test_runbook.py`) |
| J12 | Auto-audit `audit/self-audit/AUDIT-0001.md` établi à partir de mesures, sans modification de la Factory |

## Refus explicites (guide §23)

- Pas de branchement du Policy Engine en garde **globale** de l'agent : aucun agent n'étant habilité, tout
  serait refusé, y compris le travail de construction ; à décider par l'humain avec un plan d'habilitation.
- Pas de modification des réglages utilisateur de l'agent ni de l'IDE.
- Pas de tâche planifiée Windows (sauvegarde quotidienne) : proposée, à poser par l'humain.
